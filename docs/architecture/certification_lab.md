# Isolated certification laboratory

The laboratory is an authorization domain, **not** a certificate issuer or a
production release mode. Production still requires its real certificate and
release barrier. An experimental permit cannot populate certificate fields or
be submitted through Settings, the runtime API, or model tools.

## Implementation sequence and evidence boundary

1. Typed, signed exact-target permit, private installation trust/store, durable
   revocation/ownership, isolation checks and negative tests.
2. Shared authority lattice and the single hosted composition; reusable durable
   generation-budget fence, including post-pacing revalidation.
3. Private bootstrap and offline natural worker through input capture and
   `execute_agentic_runtime_turn`, with only HTTP simulated. Retain observations
   and cleanup errors; completion is not a semantic review decision.
4. Independent boundary review **before** any paid/free provider generation;
   then the bounded live corpus, independent signed review/publication and a
   separate certified API → queue → dispatch canary.

Only completed, tested stages are recorded in the delta report. The existence
of the contract does not activate a worker or satisfy P6-L/S/R. Native Gemini
needs a distinct connection/distribution/binary/effects target and native worker;
Google API authorization never covers it.

## Authority and pinning

Certificate validation remains mandatory in the production resolver. Lab permit
validation supplies a *granted experimental ceiling*, not certified capability.
Both feed one monotonic policy/tool/health/feature/execution-mode lattice. The
snapshot/audit distinguishes production certification from experimental authority.
Lab pins have no certificate ID/evidence/efforts and bind the installation, job,
permit digest and revision; imported/modified pins fail closed. Descendants
require individually named grants; the first vertical grants none.

Written persisted-schema decision: existing production-only pins may omit the
new authorization-domain extension. Their exact historical digest remains valid
without rewriting the pin or session. This compatibility is production-only;
lab pins cannot omit the domain or use the historical digest fallback. The
active Codex 14 installation is not migrated. Changes in shared queue/handoff
remain in the canonical native artifact and require explicit successor review.

## Installation and trust

Source, tenant workspace, control plane, vault, permit trust/store, evidence and
budget are explicitly configured. Before each bootstrap, canonical paths and
filesystem identities must be disjoint from the active installation, including
symlinks, nested aliases and shared Git administration. A worktree pointing back
to production's Git directory is not a separate laboratory installation.
No production bootstrap, environment-derived Mongo/endpoint/token/credential,
ambient HOME, insecure-test defaults, or production workspace is permitted.
Model actors are non-administrators. Trust, issuer/reviewer/publisher material,
evidence and budget are not tenant mounts or discoverable model tools. Actual
workspace process isolation remains Bubblewrap with network namespaces and the
real effect overlay; Full Workspace is not full host access.

Permits are immutable signed records plus monotonic CAS revocation status in an
installation-private store. Public issuer trust is reloaded on every resolution;
workers never supply a replacement trust map. A stored reference is not a bearer
authority. Execution ownership is claimed atomically and is never renewed by
restart, timeout or a second worker. Crash ambiguity stays reserved/owned until
an explicit operator recovery protocol proves absence of descendants.

## Global generation budget

The reusable fence is independent of protocol-probe round counts. Each actual
translated generation payload reserves its conservative ceiling in the same
operator-owned SQLite ledger. OpenRouter has 4.50 USD operational headroom within
5 USD total; Google uses a finite, free-tier-only quota, never paid fallback.
Prices, endpoint/model, credential, permit expiry/revocation and ownership must
be fresh immediately before HTTPS, including after pacing. Cancellation,
crashes and ambiguous responses never refund reservations. Stream failures halt
subsequent requests durably. A ledger's `free_tier` label is not proof of the
provider project's actual billing tier: operator verification is still required.
