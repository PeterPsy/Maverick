# Generated Artifact Policy

Maverick currently commits selected generated frontend artifacts under `apps/*/frontend/dist/`.

This is intentional for built-in apps that must mount in a fresh checkout before a frontend rebuild step is available.

## Rules

- Edit source files when source exists.
- Rebuild the app after changing source.
- Commit generated `frontend/dist/` only for built-in apps whose contract serves that directory.
- Do not commit local runtime output, logs, caches, workspace data, screenshots, or temporary exports.
- Keep Design Studio's signed OpenDesign release assets under ignored
  `apps/design-studio/service/artifacts/` and materialized bundles under ignored
  `apps/design-studio/service/vendor/open-design/`. Commit only their canonical
  digest contract and the redaction-safe OCI, migration, product, and global
  acceptance records. Product evidence must be regenerated by the E2E command,
  never copied from a workspace runtime/log directory.
- Do not commit source maps that expose local paths unless explicitly reviewed.
- CI should verify that source-built apps can rebuild successfully.

## Hygiene Check

Use the repository hygiene reporter before review when the working tree contains generated or local runtime noise:

```bash
python3 scripts/check_workspace_hygiene.py --json
```

The command is read-only. It separates tracked `frontend/dist` churn, workspace runtime/log/tmp changes, and cache directories such as `node_modules` and `__pycache__`. Use `--strict` when a CI or pre-merge step should fail on any reported finding. Do not use the report as permission to delete unrelated dirty work; separate intentional source changes from generated artifacts first.

## Rationale

Maverick's app contract serves declared static frontend output. During the pre-release period, committed dist assets keep app mounting deterministic while the app packaging and release pipeline matures.

This policy should be revisited before the first stable release.
