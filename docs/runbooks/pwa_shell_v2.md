# Base Shell Service Worker v2R Operations And Acceptance

This runbook operates and validates the M2R transparent standard-shell cache.
It authorizes no private read model, Storage file byte, prompt, mutation, model,
agent, tool, capability, authority record, or persistent outbox.

## Owned artifacts and caches

- Build manifest: `apps/base-shell/frontend/dist/maverick-frontend-assets.json`
- Worker source: `apps/base-shell/frontend/public/sw.js`
- Generated worker: `apps/base-shell/frontend/dist/sw.js`
- Standard navigation fallback: verified `index.html`
- Versioned shell cache: `maverick-static-v2:<build_id>`
- App/widget bundles: public platform-origin HTTP cache with verified manifest
  policy, CORS/CORP, and gzip/Brotli
- Exact migratable legacy caches: `maverick-app-static-v2` and
  `maverick-base-shell-v3`

There is no alternative HTML document, synthetic product response, or global
transport-status UI. No operation in this runbook may clear the whole origin.
IndexedDB, OPFS, and unrelated Cache API names are outside worker ownership.

## Routing assertions

- `/`, `/app`, and `/app/*`: network-first with bounded timeout, then verified
  standard `index.html` from the active build cache.
- Non-shell navigations: no service-worker fallback.
- Immutable shell assets: cache-first only after size/SHA-256 verification.
- Other selected static assets: network-first, then verified cached bytes.
- App/widget HTML: Core rewrites quoted `/apps/<app_id>/assets/...` `src`/`href`
  values to the exact public platform origin.
- App/widget assets: browser HTTP cache; only manifest-verified immutable bytes
  receive one-year immutable policy, and public CORS/CORP plus compression are
  preserved. The shell worker does not intercept these isolated-client loads.
- API, SSE, WebSocket, backend, sidecar, range, non-GET, cross-origin, and
  `/sw.js`: complete bypass.

A first navigation without a successfully installed cache may fail normally in
the browser; it must never receive generated fallback HTML.

## Update and interrupted-install drill

1. Open build A in two tabs and confirm both are controlled by `/sw.js`.
2. Deploy build B. A worker-only, fallback-selection, or precache change must
   produce a new `build_id` and cache name.
3. Block one B precache request. Confirm B installation fails, its incomplete
   cache disappears, build A remains active, and both tabs continue unchanged.
4. Restore the request and call `registration.update()` or reload with working
   transport.
5. Confirm B waits while A still owns clients. No connectivity indicator or app
   icon is repurposed for this lifecycle state.
6. Close every A client and confirm normal service-worker activation selects B.
   An explicit operator test may send `MAVERICK_SKIP_WAITING`; it is not a
   transport-recovery action.
7. Confirm activation removes only obsolete `maverick-static-v2:*` caches and
   the two exact legacy caches. Unrelated Cache API entries, IndexedDB, and OPFS
   remain.

## Corruption and recovery drill

1. While online, delete or replace one response in the active versioned cache.
2. Request an immutable asset. The worker rejects bad bytes, fetches and verifies
   declared size/SHA-256, and repairs the entry best-effort.
3. Delete one selected revalidated static asset and remove transport.
4. From DevTools, send `{type: "MAVERICK_RECOVER"}` to the active worker.
   Recovery must report `MAVERICK_SW_RECOVERY_FAILED` without deleting the
   verified entries that remain.
5. Restore transport and repeat. The worker reports `MAVERICK_SW_RECOVERED` and
   every generated precache record is present.

Recovery has no product dialog and never changes the normal shell tree.

## Kill switch and rollback

Set the backend environment and restart through the operator-managed service:

```bash
MAVERICK_FEATURE_PWA_SERVICE_WORKER_V2=off
```

Confirm `/api/pwa/config` returns schema `maverick.pwa-config.v2`, generation
`v2`, and `service_worker.enabled: false`. On the next reachable shell load the
client unregisters the root worker and deletes only:

- `maverick-static-v2:*`;
- `maverick-app-static-v2`;
- `maverick-base-shell-v3`.

An unreachable config endpoint is not a kill-switch decision: the client keeps
the functioning worker and changes no origin storage. Re-enable the flag, reload
with working transport, and confirm a fresh verified cache installs.

The remaining cache-centric gates are:

- `MAVERICK_FEATURE_PWA_DATA_CACHE` (default off);
- `MAVERICK_FEATURE_PWA_APP_CACHE_<APP_ID>` (default off and subordinate);
- `MAVERICK_FEATURE_PWA_STORAGE_FILE_CACHE` (default off).

There is no mutation-outbox flag or legacy file-cache alias.

## Physical Safari and installed-PWA release gate

Automated Chromium/WebKit results are development evidence only. Execute every
row against the same reviewed build. Clear only the tested container before its
first run.

| Container | First open + verified precache | Warm transport loss preserves tree | Restart uses standard shell/loading | Recovery has no mode UI | Update/recovery/kill switch | Evidence |
|---|---|---|---|---|---|---|
| Minimum supported Safari on macOS | pending | pending | pending | pending | pending | pending |
| Current Safari on supported macOS | pending | pending | pending | pending | pending | pending |
| macOS Dock-installed web app | pending | pending | pending | pending | pending | pending |
| Minimum supported Safari on iOS/iPadOS | pending | pending | pending | pending | pending | pending |
| Current Safari on supported iPhone | pending | pending | pending | pending | pending | pending |
| iPhone Home Screen web app | pending | pending | pending | pending | pending | pending |

For each row record only device model, OS/browser version, build id, UTC
timestamp, and pass/fail. Reject the row if:

- transport loss changes the normal shell or removes an already-mounted iframe;
- a cache miss renders a dedicated network page/error instead of normal loading;
- any global Online/Offline copy, marker, dialog, or app-icon replacement appears;
- a non-shell navigation receives a product fallback;
- API/SSE/WebSocket/backend/sidecar/range traffic is intercepted;
- `401`/`403` remains in retry/loading or uses a stale authorization result;
- an interrupted update harms the prior worker/cache; or
- activation, recovery, or rollback removes IndexedDB, OPFS, or an unrelated
  Cache API entry.

Also open the build once in Safari private browsing. Denied or ephemeral storage
is supported server-first degradation: rendering must not crash, claim durable
availability, or block a valid network response.
